# DRINKS DISCOVERY JAPAN（DDJ）

小さな酒蔵・蒸溜所のお酒を紹介する Web サイトです。
HTML・CSS・JavaScript だけで動く静的サイトなので、ビルドは不要です。
GitHub にファイルを上げると、Vercel が自動でサイトを更新します（和食材カレンダーと同じ仕組み）。

## フォルダの中身

| 場所 | 内容 |
|---|---|
| `index.html` | トップページ |
| `products.html` | お酒を探す |
| `finder.html` | 味わい診断 |
| `breweries.html` | 酒蔵・蒸溜所を訪ねる |
| `regions.html` | 産地から探す |
| `learn.html` | 日本のお酒を知る（STORIES） |
| `admin.html` | 管理画面（検索エンジンには載りません） |
| `assets/` | 見た目（style.css）と動き（app.js） |
| `img/` | 画像。同じファイル名で上書きすれば差し替わります |
| `data/breweries.json` | 公開中の酒蔵・銘柄データ |
| `template/` | 酒蔵さんに配る Excel 入力テンプレート |

## 最初の公開手順

1. GitHub の KAI-tabegoro に新しいリポジトリ（現在は `kuranowa`）を作ります。
2. このフォルダの中身をすべてリポジトリにアップロードします（「Add file」→「Upload files」）。
3. Vercel の washokuzaicalendar チームで「Add New…」→「Project」を選び、作ったリポジトリを Import します。
   - Framework Preset は「Other」のままで構いません。ビルドコマンドも不要です。
4. 「Deploy」を押すと、数十秒で `〜.vercel.app` のアドレスで公開されます。
5. 独自ドメインを使う場合は、Vercel のプロジェクト設定「Domains」から追加します。

## 公開準備中の設定（正式公開時に外す）

今はサンプル段階のため、検索エンジンに載らない設定にしています。

- 各HTMLの `<meta name="robots" content="noindex,nofollow">`（`admin.html` 以外は正式公開時に削除）
- `robots.txt` の `Disallow: /`（正式公開時は `Disallow: /admin.html` に変更）

この設定は「検索に出さない」だけで、アドレスを知っている人は見られます。
特定の人だけに見せたい場合は、Vercel のプロジェクト設定「Deployment Protection」で制限してください。

## 酒蔵データの更新手順

1. `admin.html`（例：`https://〜/admin.html`）を開きます。
2. 酒蔵さんから届いた Excel をドロップして取り込みます。
3. 一覧の「確認」で表示を確かめます。
4. 「公開用データを保存」を押して `breweries.json` を保存します。
5. GitHub の `data` フォルダに `breweries.json` をアップロードし、「Commit changes」を押します。
6. 1〜2分でサイトに反映されます。

- 作業中の内容は、そのパソコンのブラウザに残ります。別のパソコンで続きをする場合は、先に公開してください。
- 管理画面は誰でも開けますが、サイトを書き換えられるのは GitHub に上げられる人だけです。
- 公開中の酒蔵がひとつもない間は、見本（架空データ）が表示されます。

## 取引データ（商品一覧）の取り込み

取引システムから書き出した商品一覧（1行1商品のExcel）は、管理画面にそのままドロップすれば取り込めます。

- 「仕入元事業者名」ごとに酒蔵としてまとめます（「株式会社〇〇」と「〇〇株式会社」のような表記違いは同じ酒蔵として扱います）。
- 小分類から種類を決めます。焼酎（芋・麦・その他）と泡盛は「焼酎」、ウォッカ・その他酒類は「リキュール・その他」です。
- アルコール度数・精米歩合などは「備考」から、容量は「規格」から読み取ります。
- 価格・入数・最低出荷数量などの取引条件は取り込みません。
- 同じ酒蔵・同じ商品名・同じ容量の行（入数違いなど）は1つにまとめます。
- もう一度取り込むと、酒蔵さんが入力した味わい・紹介文などは残したまま、商品名や度数を更新します。取引データから消えた銘柄は掲載から外れます。

取り込んだら、ほかの更新と同じく「公開用データを保存」→ `data/breweries.json` を上書き → Commit → Push で反映します。

## 商品写真の追加

写真がない銘柄は「NO IMAGE」と表示されます。写真を追加するときは次のとおりです。

1. 写真を `img/products/<仕入元事業者ID>/<取引データの画像ファイル名（拡張子なし）>.webp` の名前で置きます。
   例：取引データの写真欄が `/uploads/maker/40/138.jpg` なら `img/products/40/138.webp`
2. `img/products/index.json`（写真の一覧）に同じ名前を追加します。
3. 管理画面で取引データを取り込み直すと、一覧にある写真が自動でひも付きます。

写真は横・縦とも640px以内のWebP形式に縮小すると、1枚10KB前後に収まります。

## 画像の差し替え

`img/` の中の同じファイル名で上書きしてください。推奨サイズは次のとおりです。

| ファイル | 用途 | 推奨サイズ |
|---|---|---|
| `hero-ddj.jpg` | トップのメインビジュアル（文字なし） | 横 1670 × 縦 405px 以上（同じ比率） |
| `t-sake.jpg` 〜 `t-liq.jpg` | トップの種類タイル 8 枚（sake / shochu / whisky / gin / rum / beer / wine / liq） | 横 390 × 縦 500px 程度（縦長） |
| `p-learn.jpg` | トップ下「Learn Japanese Drinks」 | 横 1600 × 縦 440px 程度 |
| `p-regions.jpg` | トップ下「Regions」 | 横 1600 × 縦 440px 程度 |
| `ddj-mark-dark.png` | ヘッダーのロゴマーク（黒・透明背景） | 縦 240px 以上 |
| `ddj-mark-white.png` | トップのロゴマーク（白・透明背景） | 縦 300px 以上 |
| `favicon.png` / `apple-touch-icon.png` | ブラウザのタブ・スマホのホーム画面のアイコン | 64px / 180px 正方形 |
| `pattern.jpg` | 下層ページ見出しの和柄背景 | 横 1600px 以上 |
| `r-*.jpg` | 産地 7 枚 | 横 400 × 縦 270px 程度 |
| `c-*.jpg`・`i-*.png` | 日本のお酒を知る ページの写真・アイコン | — |

いまのタイル・バナー・ロゴは一覧画像からの切り出しのため小さめです。高解像度の画像ができたら同じ名前で上書きしてください。
縦横比が変わる場合は、`assets/style.css` の該当箇所も調整が必要です。
